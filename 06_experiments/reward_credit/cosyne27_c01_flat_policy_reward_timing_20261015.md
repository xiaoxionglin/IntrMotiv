## Scientific question and existing-run audit

C01 directly explores without a commanded DG goal, worker-hit bonus, or goal graph. Its flat-policy reward is computed for each decision as $r_{\mathrm{flat},t}=0.1(71-d_t)$, where $d_t$ is the internal temporal-distance statistic; many resulting values are exactly zero. The pinned COSYNE source computes this in `legacy_reward_streams`, then writes the decoder reward to the PPO reward buffer in the non-HRL branch. Its `--hrl_distance_bonus_mode=constant` flag is evaluated only for goal-conditioned, target-gated worker rewards. It cannot form a C01 control. The separate `--encoder_interval_credit_mode=constant` changes the event credit reaching DG, not the flat-policy reward.

The [training catalog](../cosyne_2027/training_runs.csv) contains 27 verified C01 attempts: three September temporal references; nine October old-ablation constant/no-credit variants; ten fresh temporal/constant **encoder-credit** runs; and five fresh no-credit runs. The eleven pre-existing C01 StudySpecs in this checkout declare neither a flat-policy reward mode nor the requested $\gamma=0.999$, GAE $\lambda=0.995$ regimen. The pinned source has no flat-policy constant branch. Thus none of the 27 can estimate the proposed pull manipulation, even though the fresh ten provide a valid five-seed *push* contrast.

The established fixed-observation push result is temporal minus constant **encoder credit**: C01 DG spatial information $+0.0575$ bits per step, active-only map cosine $-0.033$, and Gaussian eligible-peak area fraction $+0.109$, each with the same directional sign in five paired seeds. These are [existing encoder-credit outcomes](../cosyne_2027/checkpoint_fields_20261011.md#identical-observations-strongest-representational-result), not evidence for flat-policy reward timing.

## Minimal flat-policy intervention

The [corrected source patch](../../hpc_runs/patches/cosyne27_c01_flat_policy_reward_timing_v2_20261015.patch), SHA-256 `28a9e73e6d3076fdc69eedf8fe4cb31479cf4094d5cb9ca396c0c2ec0c126f59`, adds `--flat_policy_reward_mode=temporal|constant` and a post-scale constant in reward units. Temporal mode returns the original decoder reward tensor unchanged. Constant mode replaces only **nonzero, reward-eligible** decisions with one fixed value, preserving exact zero decisions before the PPO buffer receives it. The code rejects constant mode in a goal-conditioned run. It leaves the encoder's temporal event credit, DG loss, architecture, environment, and reward-routing sequence unchanged. This is analogous to replacing the C05/C15 temporal worker bonus with a mean-matched constant because it removes the temporal value while preserving the recipient and reward-eligible decisions. It is a **different intervention**: C01 has no commanded hits or target-gated base reward.


The support correction is material: the archived fresh C01 seed-99 reward history has only 14.6% nonzero decisions on average over 0–2M frames, rising to 37.9% over 90–100M. The [archived history](../results/cosyne_2027_intrinsic_reward_course/histories/COS27_C01_TEMPORAL_S99.csv) is under the older policy-credit regimen and is used here only to audit reward eligibility. The [initial patch](../../hpc_runs/patches/cosyne27_c01_flat_policy_reward_timing_20261015.patch), SHA-256 `d5be13176505ff6fb2cd255a50ad7081cb50eee3966f4ea470fed2bec4faa1a9`, would have paid its constant on every decision, changing reward support. Its temporal-only job 8381905 was cancelled at 4:03 elapsed before calibration; it has no scientific endpoint. Its [submitted manifest](results/cosyne27_c01_flat_policy_reward_20261015/temporal_qualification_jobs.tsv) and [audit](results/cosyne27_c01_flat_policy_reward_20261015/temporal_qualification_audit.json) preserve the superseded attempt.
Use five paired seeds 8, 17, 41, 99, and 123, $\gamma=0.999$, GAE $\lambda=0.995$, temporal encoder event credit, and stopped PPO-to-DG gradient. The parent fresh C01 runs used $\gamma=0.99$ and implicit GAE $\lambda=0.95$, so their outcomes are context, not matched arms. A separate seed-99 temporal 2M-frame qualification under the new regimen supplies the calibration. Compute the fixed constant as the sum of `intrmotiv/reward/intrinsic_sum` divided by the total reward-eligible decision count derived from `intrmotiv/reward/intrinsic_nonzero_fraction` over a prespecified 0–2M-frame reference window. Cross-check `intrmotiv/reward/intrinsic_mean` and the known 2,048 valid decisions per learner block. The pinned runtime parses `value_bootstrap=False`, so the logged flat reward is not augmented by timeout value bootstrapping. The [count-checked reader](calibrate_dense_flat_reward.py) records the event-file hash, logged steps, valid and eligible decision counts, constant, source release, and StudySpec hash before the constant arm launches. Do not recalibrate by seed or from terminal outcomes. The original C05/C15 hit-bonus constants do not apply.

## Reusable lesson

The run catalog and StudySpecs resolved the missing cell quickly; the pinned reward branch was decisive because similarly named `CONSTANT` C01 runs changed encoder credit. A first patch application exposed a malformed test-file hunk count, corrected before the 47-test pass. The archived reward's 14.6% early nonzero fraction exposed a more important scientific flaw: an unconditional constant would change reward support, so the first qualification was cancelled and a fresh source added the support-preserving mode. The canonical print-only and submitted audits preserved the source, command, and workspace boundary. The retained 100k spatial snapshots made the complete five-age, five-seed analysis possible without another DMLab rollout; the reusable peak-input contract allowed a pooled Figure 2D mask and exact source-hash archive. For a similar study, begin with the immutable StudySpec and canonical collector, then use the archived peak coordinates and one declared spatial mask for all displayed arms.
